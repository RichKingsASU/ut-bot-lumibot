# Decision-data validity and freshness

## Safety contract

`ValidatedValue` is the shared boundary type for decision-critical input. It carries
`value`, `status`, source timestamp, computed age, provenance and reason. Its status
is one of `VALID`, `NO_DATA`, `STALE`, `ERROR`, `DISABLED`, `MALFORMED`, or a
quote-specific invalid status. Only `VALID` with a non-`None` value is valid.

`EntryReadiness.evaluate` is the centralized new-risk gate. It combines the existing
execution lease and broker reconciliation prerequisites with the strategy's named
mandatory inputs. Every invalid mandatory input adds a structured reason code and
blocks entry. This gate is not called by cancel, close, reconciliation, kill, or
flatten paths.

## Freshness and timing

* The canonical live UT strategy currently consumes the latest daily bar returned by
  Alpaca, including the current incomplete daily bar during the session. This patch
  does not change that timing. It rejects a daily input older than the configured
  36-hour ceiling; session/calendar gating remains independently required.
* Five-minute inputs use `MAX_5M_DATA_AGE_SECONDS` (default 360). Stale/empty bars
  produce no RSI and cannot authorize entry. There is no synthetic RSI 50.
* Option entry quotes default to 30 seconds and additionally require positive bid and
  ask, a non-crossed market, matching contract, timestamp, positive mid, and spread
  within the configured limit. These quality checks apply to entry, never emergency
  liquidation.
* Sentiment uses scored article timestamps and defaults to 3,600 seconds. Fetched and
  scored counts are separate. Zero scored articles never yield a numeric average.

## Zero versus missing

A measured `0.0` with `VALID` status is a business value (for example, neutral
sentiment from ten scored articles or zero broker P&L). `None` plus an explicit
non-valid status represents unavailable information. HTTP success with empty bars is
`NO_DATA`, not a zero gap. Agent timeout is `ERROR`, not `HOLD`. Account failure is
`ERROR`, not fallback capital.

## Health hooks

`ValidatedValue.health(prefix)` emits validity, status, timestamp, age, source and
reason. Combined with `EntryReadiness`, runtime state can expose `entry_allowed` and
all block reasons while separately reporting process liveness. Component useful-work
heartbeats remain the next P0; this change provides the freshness fields they consume.

## Dangerous-default inventory (2026-08-19)

| Area / pattern | Classification | Disposition |
|---|---|---|
| Backtest metrics and empty trade arrays | SAFE PRESENTATION DEFAULT / VALID BUSINESS ZERO | Unchanged; cannot authorize live risk. |
| Dashboard chart/stat empty arrays and zeros | SAFE PRESENTATION DEFAULT | Unchanged; presentation only. |
| Broker realized P&L aggregation of established rows | VALID BUSINESS ZERO | Retained; query validity is carried separately by the broker adapter. |
| `signal=0` generated by UT crossover math | VALID BUSINESS ZERO | Retained only after bar and RSI validity succeeds. |
| Empty Alpaca bar payload / fetch exception | DANGEROUS UNKNOWN-AS-EMPTY | Decision boundary maps to `NO_DATA`/`ERROR`; signal values are `None`. |
| Agent account equity `get(..., 0)` and Kelly baseline fallback | DANGEROUS UNKNOWN-AS-ZERO | Kelly fallback removed; broker failure now raises `ACCOUNT_STATE_UNAVAILABLE`. Remaining presentation-only account lines are not entry gates. |
| Regime load/feature/classifier failure → `QUIET` | DANGEROUS UNKNOWN-AS-NEUTRAL | Replaced by `NO_DATA`, `MALFORMED`, or `ERROR`, with no regime value. |
| Sentiment zero articles → neutral label/zero | DANGEROUS UNKNOWN-AS-NEUTRAL | Scored count controls validity; average is `None` unless `VALID`. |
| LLM helper failure → rule fallback | DANGEROUS UNKNOWN-AS-NEUTRAL when mandatory | Shared agent-decision validator distinguishes `ERROR`; callers must declare mandatory versus optional degradation. |
| Option collector absent quote → `[]` | DANGEROUS UNKNOWN-AS-EMPTY for entry | Entry quote validator maps absence to `NO_QUOTE`; collector storage behavior remains unchanged. |
| Watchdog account `equity` default zero | DANGEROUS UNKNOWN-AS-ZERO | Documented remaining P1 operational monitor cleanup; it does not authorize orders. |

The full repository search used the patterns requested in P0-04. Defaults in research,
simulation, migration, seeding, and test fixtures were classified as non-live and left
unchanged rather than mechanically rewritten.
